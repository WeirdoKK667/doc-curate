# workflow-detail.md · 工作流完整细则

> 每阶段的完整步骤、参数、产物文件清单与异常处置。

---

## 阶段 0：用户提供文件/参数

### 核心定位
**只做简单整理**，剩余工作由阶段 1 完成。

### agent 动作
1. 解析 4 种输入形式（绝对路径 / 目录路径 / 工作区路径 / 口述参数）
2. 用关键词识别（如 "第 5-20 页""批量"）
3. 整理 `1 源/PARAMS.md`（**仅含源文件信息**）
4. 含异则问用户；批量策略询问后决定

### PARAMS 阶段 0 输出字段（仅 4 项）
```yaml
INPUT_FORMAT: pdf              # pdf/caj/docx/pptx/epub/other
SOURCE_FILE: <absolute path>
PROJECT_NAME: <string>
WORKDIR: <absolute path>       # 即 <动作><格式>：<源文件名去后缀>/
```

### 不做的事
- 智能补全 → 阶段 1
- 信息对照 → 阶段 1
- 工作流确认 → 阶段 1
- 术语库确认 → 阶段 1

### 硬门
**不设硬门**，直接交付阶段 1。

---

## 阶段 1：探查

### 5 个核心目的

| # | 目的 | 详细 |
|---|---|---|
| 1 | **完善参数表** | 智能补全缺失字段 |
| 2 | **信息对照** | 用户提供 vs 实际探查对比 |
| 3 | **工作流确认** | 决定 PDF 文字版 vs 扫描件 OCR vs 其他 |
| 4 | **术语库确认** | 决定加载哪些本地术语库 |
| 5 | **疑问提问** | 不确定项汇总后统一问 |

### 1.1 智能补全范围

**所有字段都有默认值**，与用户提供不一致才问：

| 字段 | 默认值 |
|---|---|
| `PRINT_OFFSET` | 0 |
| `BATCH` | 5（文字版）/ 3（SCAN=on） |
| `OUTPUTS` | [md, word] |
| `SCAN` | off |
| `BILINGUAL` | off |
| `IMG_DEPTH` | full |
| `TABLE_MODE` | native |
| `FOOTNOTE` | docx |
| `SPLIT_OUT` | 0 |
| `KEEP_MARK` | on |
| `ACTION` | translate（按 INPUT_FORMAT 推断） |
| `OCR_BACKEND` | subagent_visual |
| `ENABLE_OCR` | true |
| `ENABLE_TABLE_EXTRACT` | true |
| `ENABLE_IMAGE_EXTRACT` | true |

### 1.2 信息对照呈现（清单 + md）

清单形式：
```markdown
| 字段 | 用户填 | 探查补 | 一致？ |
|---|---|---|---|
| SOURCE_FILE | D:/papers/k.pdf | D:/papers/k.pdf | ✅ |
| PAGE_START | 5 | 5 | ✅ |
| PRINT_OFFSET | (未填) | -1（推断） | ⚠️ 需确认 |
```

md 报告：`5 阶段性工作报告/探查报告.md`，含建议与警示。

### 1.3 工作流确认（主 agent 决定）

判断逻辑：
- 页字数 > 阈值 且 文本可抽取 ⇒ **PDF 文字版路径**
- 页字数 < 阈值 或 文本不可抽取 ⇒ **扫描件 OCR 路径**（SCAN=on）
- INPUT_FORMAT ∈ {caj, docx, pptx, epub} ⇒ **对应格式适配路径**

### 1.4 术语库加载

默认加载：
- **通用术语库**：`~/.translate-glossary/general/`
- **专用术语库**：`<源文件夹>/4 处理内容/专用术语表.md`

冲突解决：通用库优先；专用库可覆盖通用库；裁决写入库。

### 1.5 提问组织

探查中遇到不确定项 → 收集到探查报告末尾 → 阶段 1 完成时统一问用户。

### 1.6 硬门
**确认决策后才进阶段 2**。

### 探查报告输出
`5 阶段性工作报告/探查报告.md`，含：
- 元信息（作者、字体、加密、是否含数学字体）
- 抽样预览（首/中/尾 3 页：栏数、字符数、图数、表数）
- PDF 物理页 vs 印刷页对照表
- 参数对照表
- 工作流建议
- 待用户决策项

## 阶段 2：素材提取

### 输入
阶段 1 探查结果 + `1 源/PARAMS.md`

### 输出
`3 提取内容/` 按类型分：
```
3 提取内容/
├── 文字/                  # md 原文（供 agent 后续调用）
├── 表格/                  # md + json
├── 图片/                  # 原始图片
└── <其他>/                # 扩展
```

### 素材格式规定

| 素材类型 | 格式 | 用途 |
|---|---|---|
| 文字 | md | agent 后续读取 |
| 表格 | md + json | md 给 agent，json 给脚本 |
| 图片 | png/jpg 等 | 原图 |
| 其他 | 按类型 | 扩展 |

### 2.1 工具开关（独立控制）

PARAMS 字段：
- `ENABLE_OCR: true/false`
- `ENABLE_TABLE_EXTRACT: true/false`
- `ENABLE_IMAGE_EXTRACT: true/false`

开关控制 **agent 读取行为**——减少不必要的 agent 读取。

### 2.2 文字抽取
- 双栏判定：按 x 坐标聚类，明显两簇则按"左栏 → 右栏"输出
- 页眉页脚：用 `<!-- header -->` `<!-- /header -->` 隔离
- 每页：`<!-- page:N -->` 开头 + `<!-- /page -->` 结尾
- 公式页：数学字体字符占比 > 15% 标 `need_math_review=true`，渲染 300dpi 整页图

### 2.3 表格抽取
- pdfplumber `extract_tables`，存 md（人看）+ json（脚本读）
- 异常处置：
  - 合并单元格 → markdown 用 `> + 内容` 表现
  - 表头多行 → 拼接为单行
  - 超宽表（>8 列）→ TABLE_MODE_OVERRIDE 切换 image
  - 跨页表 → 拼接 + 标 `cross_page=true`
  - 空白表 → 标 `blank=true` 写 ISSUES

### 2.4 图片抽取
- PyMuPDF `get_images(full=True)`，按 md5 去重
- 过滤：宽或高 < 80px 或占页面面积 < 1% → `images_ignored/`
- 命名 `p{页}_{序号}.png`，按 y0 升序；y0 相同按 x0 次序
- manifest 字段：文件名、bbox、宽高、y0、ignored、md5、reused_in_pages

### 2.5 异常检测（枚举式）

每页自动检测：
- 替换字符（U+FFFD）
- 空文本 / 占位符
- 短页（< 80 字符）
- 乱码率超阈
- 跨栏跳行候选（段落数 vs 平均偏差 > 30%）
- 图多页（图占面积 > 30%）

### 2.6 manifest.json 字段

```json
{
  "page": 323,
  "text_file": "3 提取内容/文字/p323.md",
  "tables": ["3 提取内容/表格/p324_t01"],
  "images": ["3 提取内容/图片/p323_img01.png"],
  "image_count": 3,
  "need_ocr": false,
  "need_math_review": false,
  "char_count": 1216,
  "anomalies": [],
  "column_skip_suspect": false,
  "image_ignored_reason": "...",
  "reused_in_pages": [],
  "extraction_confidence": "high"
}
```

### 2.7 失败处置

- **重试**：3 次 / 30 秒（可配置）
- **自决**：先尝试自行解决
- **汇报**：无法解决时写入阶段报告 → 阶段 2 结束时报给用户

### 2.8 硬门
**汇报后等用户确认**才进阶段 3。

## 阶段 3：处理

### 输入
阶段 2 素材 + `4 处理内容/专用术语表.md`

### 输出
`4 处理内容/`（PIPELINE 动作的中间产物）

### 3.1 PIPELINE 子动作集

```yaml
PIPELINE: [translate, glossary, modular, proof]
```

| 动作 | 适用 |
|---|---|
| `translate` | 外文文献 |
| `glossary` | 建/扩专用术语表 |
| `format_convert` | 输入格式标准化 |
| `modular` | 内容结构化 |
| `proof` | 校对场景 |

→ 根据用户描述**自由搭配**，可能包含一个或多个

### 3.2 模块化三种形式

| 形式 | 适用 | 特点 |
|---|---|---|
| **自然结构** | 普通情况 | 按原文多级标题分内容（# / ## / ###） |
| **按页分割** | PDF 等需标注页码 | 显式写"第 N 页"，加 `<!-- page:N -->` |
| **按内容标签** | 检索场景 | 打 `<!-- tag:xxx -->` 标签，方便检索 |

主 agent 决定（PDF 默认按页、中文默认按结构、检索场景按标签）。

### 3.3 并行策略

- 派发 subagent 同时工作
- 默认 5 页一批
- 同时启动多批
- **具体分法由主 agent 决定**
- 每个 subagent 必须输出 `boundary_check: N-M` 自证
- 批次结果回写 PROGRESS.md 时验证该行

### 3.4 校对 vs 校验

- **校对（阶段 3 proof）**：对照原文译文检查
- **校验（阶段 4）**：术语/上下文/查证
- 区别：校对是"对"，校验是"调"

### 3.5 硬门
**不设硬门**，输出阶段报告，阶段 4 统一校验。

### 阶段 3 输出报告
`5 阶段性工作报告/处理报告.md`，含：
- PIPELINE 实际执行的动作
- 每批边界（boundary_check）
- 翻译图片数、[?] 数、术语新增数
- 校对结果

## 阶段 4：自动校验

### 输入
阶段 3 中间产物

### 输出
`5 阶段性工作报告/校验报告.md`

### 4.1 4 个子动作（按优先级 + 用户要求判断）

| 子动作 | 默认 | 说明 |
|---|---|---|
| **术语一致性扫描** | **必跑** | 任何场景都启用 |
| 跨页上下文联系 | 可选 | 视场景启用 |
| 未知术语自动查证 | 可选 | 视场景启用 |
| 预测不确定项处理方案 | 可选 | 视场景启用 |

### 4.2 校验报告章节（固定结构）

```markdown
# 校验报告

## 总结论
- 通过 / 警告 / 失败
- 关键发现摘要

## 各子动作结果
### 术语一致性扫描
### 跨页上下文联系（如执行）
### 未知术语自动查证（如执行）
### 预测不确定项处理方案（如执行）

## 发现的不确定项
- [?] 列表（含定位信息）

## 推荐处理方案
- 自动应用项 + 写入 ISSUES.md 项

## 需要用户裁决项
- 待用户决策清单
```

### 4.3 预测处理

预测出来的处理方案 → **自动应用**，做法写 `references/proofread-rules.md`。

### 4.4 硬门
**汇报后等用户确认**才进阶段 5。

## 阶段 5：导出成果

### 输入
阶段 3/4 中间产物

### 输出
`6 输出成果/` 按 OUTPUTS 列表生成

### 5.1 多产物组装

- 互不干扰情况下 **并行组装**
- 也可 **串行组装**
- **主 agent 决定**
- 一致性靠"前面步骤无问题"保障

### 5.2 完整性

- 用户无特殊说明时 **不额外提及**
- 正常情况 agent 保证使用全部素材即可

### 5.3 默认 vs 用户声明

- **用户声明优先**
- 未声明时保障默认
- agent 判断有更好形式（除 md/word）→ **询问用户是否添加**

### 5.4 交付清单

- **默认不生成**
- 交付物数量多时询问用户

### 5.5 产物组装走脚本

**禁止 agent 硬堆产物**——统一调用 `scripts/build_*.py`。

### 5.6 硬门
**不设硬门**。

## 阶段间衔接

### 中间产物完整可重跑
- 阶段 3/4 产出完整中间产物
- 阶段 5 跑脚本可重新组装产物
- 修改中间产物不必整段重写

### PROGRESS.md 维护

每阶段完成时回写：
```markdown
## <阶段名>
- 起止时间
- 产出文件清单
- 数量统计
- 已知问题
- 下一步
```

每批次完成时回写（阶段 2-4）：
```markdown
### 批次 N（页码 N-M）
- boundary_check: N-M
- 产出文件
- ISSUE 数
- 用时
```

### ISSUES.md 维护

章节必含：
1. 存疑词句（含定位 [?page-segment]）
2. 术语译法说明
3. 阶段修正（如 PDF 页与印刷页偏差）
4. 越界/补做记录

### 续跑机制

- **批次超时 30 分钟**：拆分重试
- **阶段中断**：下次开工读 PROGRESS.md 自动定位续跑点
